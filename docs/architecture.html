Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talking to a FastAPI backend that serves in-memory mock data loaded from JSON files. No database, no auth backend.

System architecture

Tech stack

Frontend

Vue 3 + Vite

  • Composition API (Reports is the exception)
  • vue-router 4, history mode
  • axios for HTTP
  • Custom SVG charts, CSS Grid
  • Home-grown i18n (EN / JA)
Backend

Python FastAPI

  • uvicorn on port 8001
  • Pydantic v2 response models
  • CORS open (*), demo only
  • Dependencies via uv (Python ≥ 3.11)
Data & tests

JSON + pytest

  • Mock data in server/data/, loaded at startup
  • Changes are lost on restart
  • pytest + FastAPI TestClient in tests/backend

Data flow: a filtered request

  1. User picks e.g. Warehouse = San Francisco in FilterBar; the value lands in the shared singleton refs of useFilters.
  2. The active view watches those refs and calls getCurrentFilters(), which maps the period to a month parameter.
  3. api.js drops any value equal to all and sends e.g. GET /api/orders?warehouse=San%20Francisco&month=2025-01.
  4. FastAPI runs apply_filters (exact warehouse, case-insensitive category/status) and filter_by_month (substring on order_date, quarters via QUARTER_MAP).
  5. The response is validated against the Pydantic model and returned as JSON.
  6. The view stores raw data in refs and derives KPIs, tables and charts via computed.

Known issues

Dashboard: PurchaseOrderModal is not defined

Dashboard.vue renders <PurchaseOrderModal> but never imports it, and no such component exists. Vue warns "Failed to resolve component"; "Create PO" cannot open a modal.

Backend: /api/purchase-orders endpoints missing

api.js calls POST /purchase-orders and GET /purchase-orders/{id}; main.py defines the Pydantic models but no routes. Purchase orders cannot be created.

Backend: /api/tasks endpoints missing (404)

App.vue loads tasks on startup; api.js also has create, delete and toggle calls. None exist in main.py, so every page load logs a 404.

Backlog page is unreachable

views/Backlog.vue exists but has no route in main.js and no nav link. Its strings are hardcoded English instead of t().

Reports page diverges from the app's patterns

Options API instead of Composition API, hardcoded API URL via raw axios, ignores the global filters, no i18n, and heavy console.log output. Covered by the workshop's expert challenge.

Minor

No favicon.ico (404 on load). CORS allows all origins, which is acceptable only for a local demo.
